# 릴리스 노트 (checkin-app)

스토어 "출시 노트"에 붙여넣을 문구와, 심사 제출 시 참고할 내부 메모를 함께 둔다.
출시 노트는 사용자가 읽는 글이라 짧게 쓴다 (Play 콘솔 언어당 500자 제한).

---

## 심사 참고 (앱 공통, 제출하지 않음)

버전과 무관하게 매번 같은 내용이라 여기 모아둔다.

- **로그인 계정이 필요 없다.** 키오스크 앱이며 매장 관리자가 최초 1회 지점 로그인을
  해두면 이후 회원은 전화번호 뒤 4자리 또는 QR 로 입장한다. 심사자가 별도 계정 없이
  첫 화면(번호 입력)까지 확인 가능하다.
- **카메라 권한**은 QR 스캔과 안면등록에 쓴다. 권한 거부 시에도 번호 입력은 동작한다.
- 개인정보 표시는 마스킹한다 — 이름 `홍*동`, 생년월일 `****-03-15`,
  전화번호 `010-99**-6666` (뒤 4자리는 입력자가 방금 넣은 값이라 그대로 노출).
- 본인 선택 화면은 조작이 10초 없으면 자동으로 번호 입력으로 돌아간다.
- **서명 설정이 없다.** `app/build.gradle.kts` 에 `signingConfigs` 가 없어
  `assembleRelease` / `bundleRelease` 산출물이 미서명이다. Play 업로드 전에
  keystore 와 서명 설정이 필요하다.

## 1.2.0 (versionCode 13) — 2026-09-16

### 출시 노트 (스토어 붙여넣기용)

```
로그인 만료 안내와 안정성 개선

• 태블릿 로그인이 만료되면 안내 창이 뜨고, 확인 후 다시 로그인할 수 있습니다
• 로그인이 거절된 이유(승인 필요, 계정 종류 등)를 화면에 그대로 보여줍니다
• Android 16 지원
```

### 기술 변경

- **관리자 토큰 만료 처리** (`SessionManager.expire` / `AdminTokenRefresher.ensureValidOrExpire` /
  `SessionExpiryViewModel` / `SessionExpiredDialog`). 상주 태블릿은 90일 토큰이 만료돼도 앱이
  모른 채 "QR 코드가 유효하지 않습니다"만 반복해 센터가 앱 버그로 오인했다.
  만료가 확정되면 세션을 비우고(자동로그인 자격증명은 유지) 어느 화면이든 팝업 → 확인 → 로그인.
  감지 3경로: 인터셉터(갱신 실패+exp 경과, 관리자 Bearer 요청 401) / 홈 진입 / 10분 주기.
  회원 Bearer·`X-Admin-Token` 만 실린 요청의 401 은 만료로 보지 않는다.
- **로그인·QR 인증 406 은 서버 메시지 그대로.** 서버(backend PR #327)가 사유를 구분해 준다 —
  "체크인앱 사용 승인이 필요합니다. 관리자에게 문의해 주세요" / "기업회원(매니저) 계정만 체크인앱에
  로그인할 수 있습니다" / "태블릿 관리자 로그인이 만료되었습니다. 다시 로그인해 주세요".
  종전엔 406 을 "계정이 비활성 상태입니다"로 뭉갰다.
- targetSdk/compileSdk 36, Gradle 8.11.1, AGP 8.10.1. 앱 아이콘 교체.
- 1.1.1 의 결석 수업 입장(ABSENT) 변경 포함 — 1.1.1 이 스토어에 안 올라갔다면 이 버전으로 같이 나간다.

### 🔴 업로드 전 확인

- 🚨 **서버 배포 순서.** backend PR #327 이 checkin-kiosk 운영에 배포된 뒤 앱을 올린다.
  구버전 서버라도 앱은 동작하지만(만료 팝업은 앱 단독 판정), 406 사유 메시지는 서버가 있어야 나온다.
  운영 DB 선작업(`center.KIOSK_LOGIN_YN` 컬럼 + 8센터 승인 백필)은 2026-09-16 완료.
- 🚨 **로그인 계정.** 이 버전 서버부터 **기업회원(MANAGER) 계정 + SUPERADMIN 승인 센터**만 로그인된다.
  직원(EMPLOYEE)·운영자 계정으로 로그인해 둔 태블릿은 다음 재로그인 때 막힌다 — 배포 전 운영 로그 기준
  태블릿 로그인 계정은 전부 MANAGER 였다. 새 지점은 CRM 기업회원 상세 "체크인앱 로그인" 스위치로 승인.
- **자동로그인 체크 권장.** 자동로그인이 저장된 태블릿은 만료 전에 조용히 갱신되어 팝업 자체가 안 뜬다.
  저장 안 된 태블릿만 90일마다 팝업 → 수동 재로그인.
- 1.1.1 의 결석 입장 선행 조건(backend `80a9ddcc`·`6da78610`)은 origin/main-v1 에 머지돼 있다.
  운영 kiosk 에 배포됐는지는 서버 리비전으로 확인할 것.
- 서명 설정 없음 — 위 "심사 참고 (앱 공통)" 참조.
- 스토어에 이미 versionCode 13 이 있으면 업로드가 거부된다. 콘솔에서 확인할 것.

## 1.1.1 (versionCode 12) — 2026-08-25

### 출시 노트 (스토어 붙여넣기용)

```
결석 처리된 수업도 입장할 수 있습니다.

• 오늘 수업이 결석으로 처리됐어도 카드를 눌러 입장할 수 있습니다
• 입장하면 출석으로 정정되고, 잔여 횟수가 추가로 차감되지 않습니다
```

### 기술 변경

- `CheckinScreen` 의 입장 가능 상태에 `ABSENT` 추가
  (`CHECKABLE_RESERVATION_STATUSES = ATTENDED / RESERVED / ABSENT`).
  예약 카드 활성화와 입장 버튼 활성화 두 곳이 같은 목록을 본다.
- 차감 안내 문구 조건을 `NON_DEDUCTING_RESERVATION_STATUSES = ATTENDED / ABSENT` 로 정리.
  결석 건은 결석 확정 시점에 이미 차감이 끝나 있어 서버가 추가 차감을 하지 않는다.
  실제로 안 깎이는데 "-1회 차감"을 띄우면 회원이 두 번 깎인 걸로 오해한다.

### 🔴 업로드 전 확인

- 🚨 **서버를 먼저 배포해야 한다.** 결석 입장은 서버가 출석으로 정정하면서
  노쇼 이력·정원을 되돌려주는 것에 의존한다
  (`KioskCheckinService.attendReservation` 의 ABSENT 분기).
  2026-08-25 기준 이 백엔드 커밋들이 **아직 origin 에 푸시되지 않았다**:
  - `80a9ddcc` fix: 체크인앱에서 결석 처리된 당일 수업도 입장 허용
  - `6da78610` fix: admin 출결 처리도 결석 → 출석 정정 시 노쇼 이력·정원 복구

  운영에 안 올라간 상태로 앱만 배포하면 결석 예약이 구버전의 일반 차감 경로로 흘러
  **잔여횟수가 이중 차감된다** (결석 확정 시점에 이미 한 번 깎여 있다). 실데이터 손상이라
  단순 실패보다 나쁘다 — 서버 배포 확인 전에는 절대 앱을 올리지 말 것.
- 서명 설정 없음 — 위 "심사 참고 (앱 공통)" 참조.
- 스토어에 이미 versionCode 12 가 있으면 업로드가 거부된다. 콘솔에서 확인할 것.

## 1.0.8 (versionCode 9) — 2026-08-04

### 출시 노트 (스토어 붙여넣기용)

```
번호 체크인이 더 빨라졌습니다.

• 전화번호 뒤 4자리만 입력하면 됩니다 (기존 8자리)
• 뒤 4자리가 같은 분이 여러 명이면 본인을 선택하는 화면이 나옵니다
• 번호 입력 키패드 디자인을 출입등록 화면과 통일했습니다
```

### 기술 변경 (사용자 비노출)

- `BASE_URL` 을 `api-dev.bodyswitch.co.kr` → **`api.bodyswitch.co.kr`** 로 전환.
  운영 Apache 가 `/kiosk` 를 checkin-kiosk(8097) 로 프록시한다.
  (당시엔 구버전 APK 가 계속 `api-dev` 를 봐서 dev 서버를 살려둬야 했지만,
  2026-08-25 현재 `api-dev` 는 테스트용 서버다 — DB 만 운영을 공유한다.)
- `phoneLast4` / `candidateId` 요청 필드 추가. 구버전 서버는 이 필드를 모르고 400 을
  반환하므로 **서버를 먼저 배포해야 한다** (2026-08-04 운영 배포 완료).
- debug 빌드는 `local.properties` 의 `checkin.baseUrl` 로 서버를 바꿀 수 있다.
  release 는 항상 `PROD_BASE_URL` 을 쓴다.
